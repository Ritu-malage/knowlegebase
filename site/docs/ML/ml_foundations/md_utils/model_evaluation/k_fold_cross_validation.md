# K - Fold Cross Validation
- Measures how well your model is performing
- When we are evaluating the  performance, we use the test data, but there is a possibility that  we have  the model might be performing well for another variant of test   model may not perform well to handle this case  validation is performed.
- Without the K fold cross validation, we were getting one set of matrices that is generated because of the test data set
- But once  cross validation, we will get K number of metrices Because we will have K validation sets
- If at all the metrics generated by the validation sets looks good then it implies that the modelling approach is good, then we finally train the  the entire training data  and then perform the  the test data set
- The validation set is created from the training set, which is different from the test set
- If at all the aggregated scores generated by the validation  is not good, then we will have to adjust the hyper parameters or change the model
- The other approach is to just have training set and the validation  and ignore the test data set as we have already performed testing  K validation sets


# Working of K fold cross validation

- First break, the training data set into K fold, which implies K subset
- Use one of the folds as the validation set and use the remaining folds as the training data
- So for the next, Iteration, use a different folder as the validation set
- Each fold, which is treated as the validation set in each iteration will not be seen during the training process
- Do this until each, and every fold behaves as a validation data set

# Implementation
- K fold cross validation must be applied after training the model

```python
from sklearn.model_selection import cross_val_score
accuracy = cross_val_score(
    estimator = model,
    X = X_train,
    y = y_train, # Optional, as its not used in unsupervised learning
    cv = 10, # No of folds to be created, usually 10 fold are used
)
```
- When the dataset is very huge, in order to make sure that K fold cross validation runs faster you would want to use all the available CPUs, thus in this case add another hyperparameter called `n_jobs = -1`. This will ensure that all the available CPUs are utilized
- `accuracy` will hold the accuracies of 10 folds
